2A drawing is written as a spec and drawn by the runtime2 min

The agent writes a JSON spec — boxes placed on a grid, connections, up to three flows of one-sentence steps — and plain HTML for depth. It never writes coordinates, colours or animation. That is what makes every drawing behave the same, and what lets the audit count a drawing's caps without a browser.

Recipes, not rules. AGENTS.md gives an agent seven: a whole system, the inside of one box, one request in order, what fails and what then, two options side by side, a system inside a report, and a system too big for twelve boxes.

why a grid and not auto-layout

A grid is deterministic: the same spec draws the same picture every time, the audit can reason about it statically (two boxes in one cell, a straight line through a box), and an agent can place boxes by reading the story left to right. Auto-layout would save the agent a decision and cost the reader a stable picture. You chose the grid for now; it can change later without touching a spec's meaning.

3Everything you type lands in a sidecar that I read back2 min

Nothing you type is stored in the HTML. Ticks, pastes, exit codes, notes on steps and notes on drawing boxes all go to <doc>.flow.json beside the page, keyed by ids that never change. I can rewrite the page freely; your input re-attaches on load.

error is not fail. fail: the command ran and the target said no — evidence about the system. error: the interpreter rejected the command, so the target was never asked — evidence about my playbook. Verdicts are re-derived from the current rules every time the page loads and every time I read them back.

4The audit turns the standard into exit codes, layout included2 min
MeasuredHow
22 report capsfrom the markup: card slots, headers, row kinds, steps, words at rest
19 caps per drawing canvasfrom the spec, for the root and every segment
5 layout capsheadless Chrome on ?audit=1: screens at rest, crossings, boxes hit, labels shrunk, zone labels crossed
12 author checksunfilled slots, four paste checks, fragile regexes, row kind against content, and the spec's ids, references, vocabulary, grid and routing

The unfilled check reads the templates, so a scaffold that was built but never written fails on that and nothing else. The fragile-regex check runs every data-pass and data-fail alternative against real PowerShell, bash and Python error text, and names the word it matched inside.

what the audit still cannot tell you
  • Whether a command parses. That needs an interpreter per language, and the toolkit installs nothing. Parse-checking is the agent's obligation.
  • Whether a pass condition can be falsified by what the command really prints.
  • Whether a drawing tells the truth. It measures shape and budget, not accuracy. Your notes on boxes are how that comes back.
