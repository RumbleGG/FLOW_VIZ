Hand it back

cAn inserted step is named b3a, so no id ever moves2 min

Ids are join keys: what you paste is filed under one. So a step added between b3 and b4 cannot take b4's name, and it should not take a number that lies about its place either.

Name itWhat follows
b3a: the anchor plus the next free letter pickb4 keeps its name and its output; "look at b3a" means one step; a second insert is b3b; a letter is never handed out twice
b5: the next free numberthe numbers stop matching the order, and the audit fails the report for it
renumber b4 to b5 with flowviz relabelevery capture moves, a tab left open gets 409, and "look at b4" changes meaning mid-run
  • Steps added after b3 queue behind each other: b3a, b3b, b3c. Before the first step of a row the anchor is b0, so the first one there is b0a.
  • Removing writes a tombstone (gone), never a delete. The load merge is a union, so a deleted key would come back from the copy in the other store, and a removed id is never reused.
  • The audit's naming check learns one shape, a row letter, a number and one letter, for steps a fold brought in. It fails nothing it passes today, so this is a minor version.
  • Carried values work unchanged: {{b3a.VER}} already matches the token pattern, once the fold gives b3a a data-emit.

An added step's output, tick and note use the keys every step already uses, so Save evidence, the progress count and data-after dimming reach it without new code. Its chip reads captured, not no match: there is no pass rule to blame until the fold writes one.

How each addition ends

What changes, where

FileChange
template/flow.jsdraw added steps and the to-do section from state; merge() keeps keys it does not know; Copy captures and Save evidence carry both; t and the pill button
template/flow.cssthe insertion look, the to-do section, quick capture, print rules
SPEC.md · AGENTS.mdschema 5 (§6), the b3a shape (§1.2b), and a short section for agents: read additions back, then fold, reword or carry them
bin/flowviz-captures.py+ lines in place, a to-dos block, both in --json
bin/flowviz-fold.py (new)write added steps into the source under their ids; stamp them folded; back the sidecar up first
bin/flowviz-results.pyopen "do after" to-dos are offered as Next; the archive gate names any still open
bin/flowviz-audit.pynaming accepts b3a; what a human added is left out of the caps; a note when a sidecar beside the page holds unfolded additions
bin/flowviz-serve.pykeep any top-level key a PUT leaves out; the index lists open to-dos per page

Without the merge fix, a page built before 3.1.0 erases them. flow.js's merge() copies only the keys it knows, so an older page's next save writes a sidecar without added and todos. Fix it in both places: serve keeps any key a PUT leaves out, and merge() keeps keys it does not know. The prototype works around it by reading both stores itself.
